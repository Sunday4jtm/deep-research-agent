# LLM 应用与 Agent 基础

## Function Calling（工具调用）

Function Calling 让模型在对话中输出"我要调用哪个函数、参数是什么"的
结构化决定，由应用侧真正执行函数，再把结果交回模型继续推理。要点：

- 工具的 JSON Schema 描述越清晰，模型选对工具的概率越高；
- 工具执行发生在应用侧，模型只是"决策者"——沙箱与权限控制在应用层做；
- 模型可能选错工具或编造参数，调用前要校验参数，失败信息要回喂给模型。

## ReAct 循环

ReAct（Reason + Act）是最基础的 Agent 循环：模型先思考要做什么（Reason），
再调用工具（Act），观察结果（Observation），循环直到能给出最终答案。
生产实现通常用"最多 N 轮"的硬熔断防止死循环。

## RAG（检索增强生成）

RAG 把外部知识检索和生成结合：先检索相关片段，再把片段放进提示词，
要求模型只依据片段回答并标注引用。它能缓解幻觉、让答案可溯源，
但单轮检索有天花板：复杂问题需要拆解、追问和交叉验证。

## Agentic RAG 与多跳研究

把 RAG 从"检索一次"升级为"规划-检索-验证-综合"的循环，就是 Agentic RAG：

1. **规划**：把研究问题拆成多个互补的子问题；
2. **检索**：对每个子问题取证，公网与私有知识库可以混合；
3. **验证**：检查证据覆盖度，有缺口就生成追问再检索（有轮数上限）；
4. **综合**：汇总证据生成带引用编号的报告，未覆盖的部分明确披露。

## 幻觉抑制的实用手段

- 要求答案中的每个论断都标注证据编号，无证据不落笔；
- 提示词中明确"资料未覆盖时直接说明未覆盖"，并给拒绝范式；
- 温度调低（0 附近）降低发散；
- 关键场景加一层"引用回填校验"：报告里的引用编号必须能在证据列表中找到。

## 结构化输出与降级

要求模型输出严格 JSON 时，国产模型高峰期会偶发"不按格式、直接回一段
自然语言"。可靠的做法是三级降级：优先结构化输出接口；失败后改普通调用
加 JSON 提取；仍失败用确定性模板兜底。任何优化都不能成为新的故障点。
