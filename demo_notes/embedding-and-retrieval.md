# 向量嵌入与检索

## 什么是 Embedding

Embedding 把离散的文本映射成稠密向量，语义相近的文本在向量空间中距离更近。
检索场景的用法是：把文档切块后全部向量化建索引，查询到来时把查询也向量化，
用相似度（最常见是余弦相似度）找出最近的若干块返回。

## 常见中文 Embedding 模型

- **BGE 系列**（BAAI）：中文检索基准（C-MTEB）上表现强，社区维护活跃，
  常用 small/base/large 三档，small 版体积小、CPU 也能跑，适合本地部署。
- **M3E**：中文通用语义向量模型，短文本语义相似度表现不错，推理轻量。
- **text2vec 系列**：训练数据与目标多样，适合作为对照基线。

选型的核心依据是**在自己语料上的检索召回**，而不是榜单分数：同样的模型
在不同领域语料上差距可能很大。此外还要考虑维度（影响存储）、推理速度、
许可证与是否可本地部署。

## 相似度度量

余弦相似度只看方向不看模长，是文本检索的主流选择；点积在向量已归一化时
与余弦等价。BGE 系列官方建议对查询和文档做归一化后再算余弦。

## 混合检索：关键词 + 向量

纯向量检索懂语义但会漏精确术语（模型名、编号、缩写），BM25 等关键词检索
对术语极其灵敏但不懂同义改写。两者互补：

1. 向量通道取 Top-k；
2. BM25 通道取 Top-k；
3. 用 **RRF（倒数排名融合）** 合并两路结果：每个文档的得分为
   `1/(rank_a + k) + 1/(rank_b + k)`（k 常取 60），
   在两路都靠前的文档获得高融合分。

混合检索通常能把中间位次的命中率显著拉高，是对抗"措辞敏感"的第一手段。

## 查询改写与多跳检索

用户问题的措辞经常与文档用词不一致。查询改写（MultiQuery）让模型把问题
改写成多个角度的查询，各自检索后合并去重，可以缓解措辞敏感问题。

多跳（multi-hop）检索指：第一次检索的结果暴露出新的关键概念后，用它们
生成第二轮查询，迭代直到证据充分或达到轮数上限。多跳能回答单轮检索
答不了的问题，代价是延迟与 token 成本上升，需要轮数上限做保护。
